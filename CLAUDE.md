## Project Overview

**Art Unbound** is a Mixed Reality puzzle game for Meta Quest 3 / Meta Quest Pro. Players assemble 3D jigsaw puzzles (with triangular tab morphology) on a floating canvas in their physical space, then hang completed artworks on real walls using spatial anchors.

- **Engine**: Unity 6 LTS (6000.3.1f1)
- **Target**: Meta Quest 3 / Meta Quest Pro (Android, MR passthrough)
- **Key packages**: XR Hands (`com.unity.xr.hands`), Meta OpenXR 2.1.0, Meta XR Core SDK 83.0.1, AR Foundation, XR Interaction Toolkit

## Build & Development

There are no automated test runners or CLI build commands. Development is done entirely inside the Unity Editor:

- **Open project**: Open the folder in Unity Hub (Unity 6.0 LTS)
- **Main scene**: `Assets/ArtUnbound/Scenes/Main.unity`
- **Build target**: Android (Meta Quest)
- **Build**: File > Build Settings > Android > Build (requires Android SDK and Meta Quest device connected)
- **Play in Editor**: Press Play — the game boots through `GameBootstrap` which positions UI ergonomically after detecting XR head tracking

## Architecture

### Entry Point & State Machine

`GameBootstrap` (`Assets/ArtUnbound/Scripts/Core/GameBootstrap.cs`) is the singleton orchestrator. It:
- Initializes all services in `Awake()`
- Manages the `GameState` enum: `Loading → Onboarding → MainMenu → ArtworkSelection → ComfortPositioning → Playing → Paused → PostGame`
- Holds serialized references to **every** controller/manager in the scene and wires their events in `SetupEventListeners()`
- All state transitions happen through `SetState()` and are coordinated here

All puzzles start in **Comfort Mode** (floating canvas at 0.4m from the user's head). Wall placement only happens post-completion for hanging artwork.

### Namespace Convention

All scripts use the `ArtUnbound.*` namespace:

| Folder | Namespace | Purpose |
|---|---|---|
| `Scripts/Core/` | `ArtUnbound.Core` | Bootstrap, wall selection |
| `Scripts/Gameplay/` | `ArtUnbound.Gameplay` | Puzzle board, pieces, snapping |
| `Scripts/Input/` | `ArtUnbound.Input` | Hand tracking, interaction raycasting |
| `Scripts/UI/` | `ArtUnbound.UI` | All menu/HUD controllers + scroll |
| `Scripts/MR/` | `ArtUnbound.MR` | Comfort mode, canvas frame, wall highlight, anchors |
| `Scripts/Data/` | `ArtUnbound.Data` | ScriptableObjects and plain C# data models |
| `Scripts/Services/` | `ArtUnbound.Services` | Save, catalog, weekly unlock, telemetry |
| `Scripts/Feedback/` | `ArtUnbound.Feedback` | Audio, haptics, frame animation |

### Core Gameplay Loop

1. **`PuzzleBoard`** generates a grid of `PuzzleSlot`s from piece count + texture aspect ratio. It calls `PieceMeshGenerator.GeneratePieceMesh()` to create procedural meshes for each `PuzzlePiece`.
2. Pieces are shuffled (`PieceShuffler`) and handed to **`PieceScrollController`** which lays them out horizontally at `(0, -0.4, 0)` local to the board.
3. **`HandTrackingInputController`** supports two modes (toggle `useControllers`):
   - Controller mode: maps trigger button → pinch events via `UnityEngine.XR.InputDevice`
   - Hand tracking mode: uses `XRHandSubsystem` (XR Hands package), detects thumb-index distance < 2.5 cm as pinch
4. **`InteractionManager`** receives pinch events, does sphere overlap (3 cm radius) + optional raycast fallback to find a `PuzzlePiece`, then drags it each frame in `HandlePinchHold`.
5. On release, `InteractionManager` calls `PuzzleBoard.TrySnapPiece()`:
   - Snap uses planar (XY) distance ≤ `snapDistanceCm` (default 2 cm from config, 15 cm depth tolerance)
   - Validates triangular morphology compatibility with neighbors
   - If outside valid range: `PuzzlePiece.ReturnToPool()` animates it back
6. When `snappedCount >= slots.Count`, `OnPuzzleComplete` fires → `ScoringController` → `PostGameController`.

### Piece Morphology

Each piece edge is `PieceEdgeState`: `Flat` (border) | `Positive` (tab out) | `Negative` (tab in). Generated by parity: `(col + row) % 2 == 0 ? Positive : Negative` for inner edges. Edges complement when Positive↔Negative or Flat↔Flat.

### Data Layer

**ScriptableObjects** (in `Assets/ArtUnbound/Data/`):
- `ArtworkCatalog.asset` — master list of all `ArtworkDefinition` assets
- `PuzzleConfig.asset` — snap distance, piece size (5 cm), thickness (0.5 cm), difficulty counts
- `FrameConfigSet.asset` — frame tier thresholds and materials

**Runtime save data** serialized as JSON to `Application.persistentDataPath/save.json`. Uses `Newtonsoft.Json` (not `JsonUtility`) because `SaveData` uses `Dictionary<string, ArtworkProgress>`.

**Score formula**: `score = floor((pieceCount × 100 / timeSec) × difficultyMultiplier × helpFactor)`
- Difficulty multipliers: 64→1.0×, 144→1.5×, 256→2.0×, 512→3.0×
- Help penalty: ×0.5 if help mode was used
- Frame tiers: Madera(0), Bronce(50), Plata(100), Oro(200+no-help), Ebano(300+no-help+256+pieces)

### UI Architecture

All UI panels extend a common show/hide pattern. `GameBootstrap.HideAllPanels()` calls `.Hide()` on all controllers before showing the relevant one. UI lives on a World Space canvas positioned ergonomically at startup (`PositionCanvasWithDelay` coroutine waits for `Camera.main.transform.position.y > 0.5f`).

Scroll for the piece tray uses **UI buttons** (not air-swipe) — swipe detection is implemented but intentionally disabled in `DetectSwipe()` to avoid accidental triggers.

## Adding New Artworks

See `docs/Guia-Agregar-Pinturas.md` for the full guide. Summary:
1. Import texture to `Assets/ArtUnbound/Artworks/` with **Texture Type: Sprite**, **Read/Write enabled**, Max Size 4096
2. Create `ArtworkDefinition` ScriptableObject via `Create > ArtUnbound > Artwork Definition`
3. Register it in `Assets/ArtUnbound/Data/ArtworkCatalog.asset`

## Key Implementation Notes

- **PieceTray position is force-corrected every frame** in `PuzzleBoard.Update()` to `(0, -0.4, 0)` local — this is an intentional workaround for drift
- **Board is placed at `DefaultPlacementDistance = 0.4f`** (same as canvas), distinct from the original design spec of 0.8m
- **`InteractionManager` uses `FindFirstObjectByType<PuzzleBoard>()`** on pinch-end — avoid having multiple `PuzzleBoard` instances in the scene
- **Piece materials are created at runtime** using shader discovery order: URP Lit → Standard → Mobile/Diffuse
- **Swipe-based scroll is disabled** — use the `ScrollLeft()`/`ScrollRight()` buttons on `PieceScrollController` instead
- `SaveDataService.SaveIfDirty()` is called on `OnApplicationPause` and `OnApplicationQuit` for auto-save
- **Artwork Hanging System**: When a puzzle is completed, players can grab the frame with a pinch gesture, and it will attach to their hand. The system uses:
  - `ArtworkHangingController` (MR namespace) — Main orchestrator managing the state flow (Idle → Grabbed → Previewing → Placing → Placed)
  - `HandAttachmentController` (MR namespace) — Makes the frame follow the hand smoothly with configurable offset and scale
  - `WallPlacementDetector` (MR namespace) — Raycasts from the frame to detect valid wall surfaces and shows a ghost preview (green=valid, red=invalid)
  - `WallAnchorManager` (MR namespace) — Creates AR anchors and persists them to `SaveData.anchoredArtworks` (note: full spatial anchor persistence across sessions requires Meta Spatial Anchor API integration)
  - `PuzzleBoard.GetCompletedFrameTransform()` and `EnableFrameInteraction()` expose the completed frame for grabbing
  - Integration happens in `GameBootstrap.OnPlaceArtworkRequested()` which is called from `PostGameController` when the player clicks the placement button
